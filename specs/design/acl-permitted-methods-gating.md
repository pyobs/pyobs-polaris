# ACL / permitted-methods gating

Status: implemented, closed.

TODO.md's own "ACL / permitted-methods gating" item, previously unaddressed: pyobs-gui's `BaseWidget._fetch_permitted_methods()`/`permitted(method)` fetches `IModule.get_permitted_methods()` once per module and gates every RPC-triggering control on membership in that set, fail-open (treat everything as permitted) if the fetch fails or the module doesn't implement it. Polaris had no equivalent anywhere - every `Button.enabled` binding across every view only ever checked motion status/interface presence.

**Wire fetch**: `XmppClient::fetchModuleInfo()` (`src/comm/XmppClient.cpp`) now calls a new private `fetchPermittedMethods()` right after `m_modules->upsert(info)` succeeds, if the module's disco#info-reported `IModule` interface declares `get_permitted_methods`. This is a second, independent RPC round trip (`jabber:iq:rpc`, via the same free `comm::executeMethod()` `XmppClient::executeMethod()`'s real-param overload already uses) - deliberately not folded into the disco#info fetch itself, a different wire protocol entirely (XEP-0030 vs RPC). On success, the returned `list[str]` decodes via `codec::toQVariant()` into a `QStringList` and lands in a new `ModuleListModel::setPermittedMethods()`; on any failure (transport error, method not implemented), nothing is written - `ModuleInfo::permittedMethods` (`std::optional<QStringList>`, new field) stays at its fresh-`upsert()` `nullopt` default, which is what "fail open" means throughout this feature.

**Storage/exposure**: a new `ModuleListModel::PermittedMethodsRole` (`"permittedMethods"`) returns `QVariant()` (undefined in QML) when `nullopt`, or the `QStringList` once fetched - same narrow-role precedent as `WindowExtentRole`/`FiltersRole`. `setPermittedMethods()` finds the row by bare JID and is a no-op if not found (the module went offline mid-fetch), same tolerance `updatePresence()` already has.

**QML consumption**: every per-module delegate that has an RPC-triggering control gained a `required property var permittedMethods` (or, for the four `SidebarPanelRegistry` panels loaded via `Loader` - `FiltersPanel`/`FocuserPanel`/`CoolingPanel`/`TemperaturesPanel` - a non-required `property var permittedMethods: null`, threaded through `SidebarColumn.qml`'s existing `onLoaded: item.xxx = Qt.binding(...)` forwarding alongside `statefulInterfaces`/`availableFilters`). A new `qml/widgets/Permissions.js` (`.pragma library`, same shape as `WireValueFormat.js`) exports one predicate, `isPermitted(permittedMethods, methodName)`, deliberately centralized rather than duplicated per-delegate the way `findInterface()`/`fieldOf()` are - a fail-open security check is exactly the kind of logic where one canonical copy matters, and it's a pure function over already-decoded data (closer in kind to `WireValueFormat.js`'s `formatValueHtml()` than to the delegate-local `findInterface()` convention).

Applied to every RPC-triggering control project-wide in one pass, per TODO.md's own "design once, apply project-wide" guidance: `RoofView.qml` (Open/Close/Stop), `TelescopeView.qml` (Init/Park/Stop, Move - both `move_radec`/`move_altaz` branches gated separately since either can fire depending on the active coordinate page, Offsets Set/Reset for both RA/Dec and Alt/Az, and the four Compass buttons via a new `compassMethod` computed property mirroring `moveCompass()`'s own `IOffsetsRaDec`-first fallback chain), `CameraView.qml` (Binning/Format/Type `ComboBox`es, and a new `exposeIsPermitted` computed property gating the Expose button on *every* RPC `applyPendingSettingsThenExpose()` might conditionally fire - `set_window`/`set_gain`+`set_offset`/`set_exposure_time`/`grab_data` - as one unit, rather than letting a partial batch fire and fail partway through on a forbidden call; Abort gated only in its real-RPC branch, not the client-side "just stop the sequence loop" one), `AutoFocusView.qml`/`AcquisitionView.qml`/`AutoGuidingView.qml` (Run+Abort or Start+Stop, plus AutoGuiding's live exposure-time `SpinBox`), `ModeView.qml` (the single "Set" button - the mode `ComboBox`es themselves only stage a selection, no RPC), `StatusView.qml` ("Clear error" → `reset_error`), and the three sidebar panels with RPC controls (`FiltersPanel` → `set_filter`, `FocuserPanel` → `set_focus`/`set_focus_offset`, `CoolingPanel` → `set_cooling`). `WeatherView.qml` and `TemperaturesPanel.qml` are untouched - both purely read-only, no commands to gate. `ShellView.qml`'s free-text RPC console is also untouched on purpose: it's not a per-method button, and the server already enforces the ACL regardless of what the client preemptively disables - this feature is a UX nicety on top of that, not the enforcement boundary itself.

**Verified live** against a real `fixtures/telescope.yaml` `DummyTelescope`, via a throwaway headless harness (this project's documented technique, `tests/comm/harness_permittedmethods.cpp` + a temporary `tests/CMakeLists.txt` entry, both deleted after use) that connected, discovered the module, and printed `PermittedMethodsRole` once it resolved: confirmed `get_permitted_methods()` really does return a plain `list[str]` (decoding correctly via `codec::toQVariant`), and that the returned method names (`init`, `park`, `move_radec`, `move_altaz`, `set_offsets_radec`, `set_focus`, `set_focus_offset`, `set_filter`, `reset_error`, ...) exactly match every string used in the QML gating above - not assumed from source, per this project's standing rule for wire behavior. Then, separately, a temporary `acl: {deny: [observer]}` block added to `fixtures/telescope.yaml` (reverted immediately after, via `git checkout`) confirmed the negative path: `get_permitted_methods()` returned an empty list for the denied sender, which `Permissions.isPermitted()` correctly treats as "nothing permitted" (not "fail open" - that only applies to `undefined`/`null`, never to a real, empty, successfully-fetched list).
